# System repository (runtime aks-argocd)

The GitOps repository of one demo system on one AKS cluster. `system.json` describes the system; everything else
follows from it.

| Folder | What it holds | Who changes it |
|---|---|---|
| `system.json` | The system: environments, deployables, the cluster, identities (identifiers only) | A pull request |
| `infra/cluster.bicep` | The AKS cluster, applied as the stack `stack-<slug>-cluster` | A pull request; job `cluster-apply` applies it |
| `cluster/` | Argo CD's Helm values and the script that installs Argo CD, the Octopus Argo CD Gateway and the Octopus worker | A pull request |
| `gitops/argocd/` | The Argo CD Applications (generated by `scripts/write-gitops.ps1`) | A pull request |
| `gitops/platform/` | Ingress, certificate issuer, the worker's rights | A pull request |
| `gitops/templates/environment/` | One environment's manifests, as templates with Octopus variables | A pull request |
| `gitops/environments/<env>/` | What runs in the environment: its manifests and each deployable's image tag | Octopus only (its Argo CD steps) |
| `octopus/` | The Octopus configuration (Terraform) | A pull request; job `octopus-apply` applies it |
| `scripts/` | The script steps of the Octopus projects, and the checks | A pull request |

## How a change reaches an environment

1. A pull request to `main` passes `env-checks` and is merged.
2. Workflow `system` configures Octopus, applies the cluster and creates a release of `<slug>-system` for the commit.
3. Octopus deploys the release to the first environment: step "Apply environment" (Update Argo CD Application
   Manifests) fills the templates of `gitops/templates/environment` and commits them to
   `gitops/environments/<env>/system`; Argo CD applies the commit, and the step waits until Argo CD reports the
   Application in sync and healthy.
4. A person promotes the release to the next environment in Octopus and signs it off; the same commit's templates are
   applied there.

An app release (`<slug>-<deployable>`, created by the app repository's release workflow) migrates the database on the
Kubernetes worker in the cluster, then step "Update deployable" (Update Argo CD Application Image Tags) commits the
image tag to `gitops/environments/<env>/<deployable>/kustomization.yaml`, and Argo CD rolls the Deployment.

## After changing system.json

Run `pwsh -NoProfile -File scripts/write-gitops.ps1` and commit what it writes; `env-checks` fails otherwise.

## Argo CD web UI

`https://argocd-<slug>.<cluster.domain>`. The account `viewer` is read-only; an administrator sets its password once
(`argocd account update-password --account viewer`). The administrator's first password is in the cluster, in Secret
`argocd-initial-admin-secret` of namespace `argocd`.
